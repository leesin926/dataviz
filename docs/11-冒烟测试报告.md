## 四、缺陷清单

### BUG-1 ｜P0 ｜系统配置与免登配置读取全链路不可用（哀悼模式端到端因此无法验收）

- 现象：`GET /api/admin/config/public/screen.mourning.enabled` → **401**（pc-web / admin 两端启动各打一次，两端控制台唯一错误源）；`GET /api/admin/config/page` → **500**；`GET /api/admin/config/key/{key}` → **500**。管理端系统配置页 0 行，开关落不了库。
- 401 定位：免登要"**网关白名单 + 服务拦截器白名单**"双白（D25）。源码两处都已加（`gateway AuthGlobalFilter.WHITE_LIST`、`common-security SecurityConfig.EXCLUDE_PATHS:39`），且 `common-security/target/classes` 编译时间 15:56 晚于源码 15:48 ⇒ **源码无问题**。直连 `http://localhost:8093/api/admin/config/public/screen.mourning.enabled` 仍回 401 `未认证或认证已过期` ⇒ **运行中的 admin-service/gateway 进程未加载新包**。
- 处置：请重启 **gateway(8080)** 与 **admin-service(8093)**（用户本机 IDEA 操作，agent 不代停代起）。重启后若 401 消失即关闭本条。

### BUG-2 ｜P0 ｜`/api/admin/config/page` 与 `/key/{key}` 返回 500（同一服务的其它分页接口正常）

- 已排除：①网关（同服务 `/api/admin/audit/page`、`/api/admin/tenant/page`、`/api/admin/license/info` 经同一网关、同一 token 均 200）；②分页参数绑定（`AuditLogController.list` 与本接口签名完全同构：`PageQuery + @RequestParam(required=false)`，工作正常）；③表结构漂移（`SysConfig` 8 个字段与 `db_admin.sys_config` 逐列一致，无 `deleted` 逻辑删除列）；④Redis 不可用（`dataviz-redis` Up；且 `/page` 路径**根本不碰 Redis**，两接口同时 500 说明故障在 mapper 层或旧包）；⑤数据本身（该行 `id=1, config_key=screen.mourning.enabled, config_value=false` 存在且 hex 正确）。
- 剩余主嫌疑：**运行中的进程是 15:48 改动之前的旧包**（旧版 `getByKey` 会把 null 值写进 `StringRedisTemplate` → `Values must not be null` → 500，`ConfigServiceImpl.java:131` 的注释正是这条修复）。`/page` 的 500 需同一份栈确认。
- 需要用户提供：**IDEA 控制台里这两个请求的异常栈**（agent 无法读取用户 IDEA 会话日志，`backend/logs/*.log` 停在 09-18）。拿到栈后一次性定位。

### BUG-3 ｜P1 ｜前端把"服务不可用"渲染成"空数据/永久 Loading"，掩盖故障

- 现象：上游 DOWN 时 Vite 代理返回 **200 + text/plain 空 body**；`/dashboard` 顶部 6 张统计卡**永久停留在 "Loading..."**，`/model`、`/alert`、`/datasource` 只表现"暂无数据"，与"真的没有数据"完全无法区分。
- 影响：用户与运维都会把"服务没起来"误判成"功能没数据"，排障成本极高（本轮实测即为此绕了一圈）。
- 建议改法（小改动，需用户点头再做）：`packages/api-client` 响应拦截里判定 `typeof data !== 'object' || data === null` ⇒ 抛"服务暂不可用"类错误；页面把该错误渲染成错误态（可重试）而不是无限 Loading。

### BUG-4 ｜P1 ｜i18n 残留：三块页面在英文 locale 下仍整页中文

- 命中页面：`/etl`（数据接入设计器，**整页中文**：任务列表/执行历史/组件库/字段映射/新建任务/保存/发布）、`/alert`（tab 未读/已读/全部 + 表头）、`/monitor`（状态列 正常/已停止 + 部分卡标题）、`/dashboard`（标题"数据看板"与卡片区混排）。
- 另有一处细节：切到英文后 `<html lang>` 仍为 `zh-CN`（两端实测），属性未随 locale 同步。
- 根因：这三块页面是**模块级 `t`/硬编码中文**产物，未纳入三轮 i18n 迁移范围（三轮只覆盖了登录页、导航、编辑器、列表类页面）。
- 口径提醒（D13）：模板内必须 `useI18n()`，新增文案两端键数必须相等。

### BUG-5 ｜P2 ｜`db_admin` 种子数据中文双重编码（latin1 连接执行了 UTF-8 脚本）

- 证据：`select hex(name) from db_admin.sys_tenant where id=1` → `C3A9C2BBCB9C…`，而"默认租户"的正确 UTF-8 应为 `E9BB98 E8AEA4 E7A79F E688B7` ⇒ 典型的 **UTF-8 字节被按 latin1 再编码一次**。
- 库/表/列字符集都是 utf8mb4（已核对 `information_schema`），所以坏在**写入时的连接字符集**，不在 DDL。
- 表现：管理端租户列表名称显示 `é»˜è®¤ç§Ÿæˆ·`；`deploy/sql/init/03-all-services-schema.sql:405` 是来源行。
- 建议：重导种子时显式 `mysql --default-character-set=utf8mb4`；已污染的行可用 `CONVERT(CAST(CONVERT(name USING latin1) AS BINARY) USING utf8mb4)` 修复。其它含中文的初始化值需按同法排查。

### BUG-6 ｜P2 ｜monitor-service 自身异常：`No qualifying bean of type 'org.springframework.scheduling.TaskScheduler'`

- 来源：`/monitor` 页面上的"当前组件错误信息"卡直接回显了该服务上报的 error message（同时注册状态 0/1 DOWN）。
- 该服务注册表由 `/api/monitor/services` 提供，属 monitor-service 侧问题；需启动该服务后复看。

### BUG-7 ｜P2 ｜权限体系数据未初始化，菜单权限页不可用

- `/api/role/list → 200 空`；`/api/permission/tree → **500**`；`/admin/menus` 因 500 显示 No data 并弹 `Request failed with status code 500`。
- 后果：RBAC（角色、菜单授权、按钮级权限码）整块无法冒烟，`admin:*:view` 权限项的实际鉴权也未验证。

### 观察项（不算缺陷，但会反复误导排障）

1. **`200 ≠ 服务正常`**（见第一章判据口径）。
2. 直连 `127.0.0.1:3100` 打不通（admin dev 只听 IPv6 `[::1]`）。
3. 自动化标签页里 `requestFullscreen` 必然被拒（需用户手势），预览页全屏按钮不能以自动化判定好坏。

## 六、本轮 X1/X2 改动自身的验证结论

**X1 组件样式必须与画布底色相反（#53）—— 通过**

- 单一来源：`shared-types/screen.ts` 的 `CANVAS_INK`（由 `CANVAS_BG_COLOR` 亮度推导，底色若改深色则整套墨色自动反向）+ `CHART_PALETTE`。
- 覆盖面：32 条内置定义 `defaultProps` 全部改用 `CANVAS_INK.*`；13 个 screen-engine 渲染组件的 fallback 同源于 `CANVAS_INK`；chart-engine `brandTheme` 重建在 `CANVAS_INK + CHART_PALETTE` 上；组件内 CSS 由 JS 注入 `--dv-ink-*` 自定义属性（表格/排行/滚动榜等）。
- 存量数据修复：`clashesWithCanvas()`（与白底亮度距离 <90 判撞色）+ `normalizeScreenInk()` 在**所有读边界**（api-client 的 `getScreen/getScreenForPlatform/getSharedScreen/cloneScreen` + 编辑器 `normalizeScreen()` 含各变体）做读时归一，`INK_PROP_TARGET` 覆盖 13 个前景色键。
- 不误伤：地图/飞线的深色 artwork（`#123152/#1a3a5f/#2a6fa8`）、视频/图表占位刻意深色的部分未被改。
- 实测：同一屏（id=6，落库 `color:#ffffff` 的文本组件）在编辑器与预览都渲染 `rgb(38,50,67)`，列表卡片封面同样可读。

**X2 哀悼模式只由全局配置驱动（#54）—— 代码与 DOM 层通过，端到端阻塞**

- 删除了逐屏灰度滤镜（`EditorCanvas.vue`、`ScreenEngine.vue` 不再读 `grayMode`），设计器不再暴露该开关；灰度**唯一来源**是 `<html>.dv-mourning` ⇒ 一次作用于整页（含侧栏菜单），杜绝"菜单不变色、只有组件变黑白"以及"关不掉"的两套状态并存。
- `watchGlobalMourning` 只在拿到 `'true'/'false'` 时才改状态，请求失败保持现状（否则管理端本地开关会被其它标签页的 401 打回去）。
- 遗留即 BUG-1/BUG-2：接口不通 ⇒ 开关既读不到也存不进，端到端待用户重启服务后走 M6。
